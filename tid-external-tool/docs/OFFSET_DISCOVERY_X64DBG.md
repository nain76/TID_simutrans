# x64dbgでオフセットを見つける方法（シンボルなし）

## 現在の状況

スクリーンショットを見ると、x64dbgでSimutransにアタッチしていますが、シンボルが見つかりません。
これは**リリースビルド**（デバッグシンボルなし）のためです。

でも大丈夫です！**メモリ検索**でオフセットを見つけられます。

---

## x64dbgでの手順

### ステップ1: 列車名を検索

#### 1-1. ゲームで列車を作成

Simutransで列車を1台作成し、分かりやすい名前をつけます（例：`TRAIN001`）

#### 1-2. x64dbgでメモリ検索

```
1. x64dbg のメニューバー → [検索] → [文字列の検索] (または Ctrl+B)
2. 検索文字列: "TRAIN001" を入力
3. [OK] をクリック
```

#### 1-3. 結果を確認

参照パネルに複数の結果が表示されます。それぞれをダブルクリックして、ダンプウィンドウで確認します。

```
例:
Address: 00007FF612345680
Dump:
00007FF612345680  54 52 41 49 4E 30 30 31  00 00 00 00 ...  TRAIN001....
```

この `00007FF612345680` が `name_and_id` のアドレスです。

---

### ステップ2: convoi_t オブジェクトの開始位置を推定

#### simconvoi.h の構造から推測

`name_and_id[128]` は convoi_t クラスの後半にあります（line 387）。

典型的な x64 ビルドでは、`name_and_id` のオフセットは **0x170〜0x1A0** 程度です。

#### 試算

```
列車名アドレス: 0x00007FF612345680
推定オフセット: 0x180 (仮)
→ convoi_t 開始 = 0x00007FF612345680 - 0x180
                = 0x00007FF612345500
```

---

### ステップ3: convoi_t のメンバーを確認

#### 3-1. convoi_t 開始位置のダンプを表示

```
1. ダンプウィンドウで右クリック → [ジャンプ] → [式]
2. アドレス入力: 00007FF612345500 (上で計算した値)
3. [OK]
```

#### 3-2. 構造体のパターンを確認

simconvoi.h から、x64での構造は：

```
Offset  Size  Member          Expected Value
------  ----  --------------  -------------------------
+0x00    8    vtable ptr      0x00007FF6........ (大きな値)
+0x08    8    vtable ptr      0x00007FF6........ (大きな値)
+0x10    8    overtaker data  小さい値
+0x18    4    wait_lock       0 or 正の整数
+0x1C    4    state           0〜15 (INITIAL=0, DRIVING=6, LOADING=7)
+0x20    2    line_update...  小さい値
...
+0x90頃  4    akt_speed       0〜500程度（現在の速度）
...
+0x180頃 128  name_and_id     "TRAIN001\0\0\0..."
```

#### 3-3. ダンプで確認

```
00007FF612345500  C0 A1 40 F6 FF 7F 00 00  ← vtable (8 bytes)
00007FF612345508  D0 A2 40 F6 FF 7F 00 00  ← vtable (8 bytes)
00007FF612345510  00 00 00 00 00 00 00 00  ← overtaker data
00007FF612345518  00 00 00 00              ← wait_lock = 0
00007FF61234551C  06 00 00 00              ← state = 6 (DRIVING)
00007FF612345520  ...
```

`state = 6` が見つかれば、正しい構造です！

---

### ステップ4: akt_speed を見つける

#### 4-1. 速度が変わる場所を探す

```
1. ゲーム内で列車を動かす（加速させる）
2. x64dbgのメニュー → [検索] → [パターン]
3. Value Type: DWORD (4 bytes)
4. 現在の速度を入力（例: ゲーム内で時速50km/h → 50）
5. 検索範囲: 先ほどの convoi_t 領域
   From: 00007FF612345500
   To:   00007FF612345700
6. 検索
```

#### 4-2. 値を絞り込む

```
1. ゲーム内で列車を加速
2. x64dbgで再検索（値が増えたものだけ）
3. ゲーム内で列車を減速
4. x64dbgで再検索（値が減ったものだけ）
5. 候補が1つになるまで繰り返す
```

#### 4-3. オフセット計算

```
見つかったアドレス: 0x00007FF612345590
convoi_t 開始:      0x00007FF612345500
→ akt_speed のオフセット = 0x590 - 0x500 = 0x90
```

---

### ステップ5: 他の convoi_t を探す（配列確認）

#### 2台目の列車を作成

```
1. ゲーム内で別の列車を作成（名前: "TRAIN002"）
2. x64dbgで "TRAIN002" を検索
3. アドレスを確認（例: 0x00007FF612346080）
```

#### 配列のパターンを確認

```
TRAIN001 の convoi_t: 0x00007FF612345500
TRAIN002 の convoi_t: 0x00007FF612346500 (仮)

差分: 0x1000 (4096 bytes)
→ convoi_t のサイズは約4KB
```

しかし、これは**配列の要素**ではありません。

#### convoi_array を探す

`convoi_array` は `vector_tpl<convoihandle_t>` なので、**ポインタの配列**です。

```
1. x64dbgで QWORD (8 bytes) を検索
2. 値: 0x00007FF612345500 (TRAIN001のconvoi_tアドレス)
3. 見つかった場所が convoi_array の要素の1つ
```

## 簡易版: 最速で name_and_id だけ見つける

### 超速手順

```
1. ゲームで列車作成: "TEST"
2. x64dbg → 検索 → 文字列 → "TEST"
3. 見つかったアドレスをメモ: 0xXXXXXXXX80
4. このアドレスの下2桁を見る:
   - 0x??80 なら、オフセットは 0x180 の可能性
   - 0x??70 なら、オフセットは 0x170 の可能性
   - 0x??90 なら、オフセットは 0x190 の可能性
5. offsets.json に設定して試す
```

### 検証方法

```python
# tid_main.py を実行
python tid_main.py

# コンソール出力を確認:
✓ Found 1 convoys  ← 成功！
  Convoy: TEST (speed: 0 km/h)

または

✗ Found 0 convoys  ← 失敗、オフセット変更が必要
```

## 実践的なヒント

### ヒント1: アライメントを利用

`name_and_id[128]` は128バイト配列なので、アドレスの下位ビットに注目：

```
name_and_id のアドレスが 0x????XX80 で終わる場合
→ 0x80 = 128、つまり 128バイト境界
→ オフセットは 0x180, 0x280, 0x380 のいずれか
→ 構造体サイズから 0x180 が最も可能性が高い
```

### ヒント2: state の値で確認

```
state の値（4バイト整数）:
0  = INITIAL (depot内)
6  = DRIVING (走行中)
7  = LOADING (積載中)

列車が走行中なら、0x1C オフセットの値が 6 になるはず
```

### ヒント3: wait_lock は通常 0

```
列車が正常に動いている場合、wait_lock = 0
0x18 オフセットが 00 00 00 00 ならOK
```

## トラブルシューティング

### Q: 列車名が見つからない

**確認**:
- 検索文字列が正確か（大文字小文字、スペース）
- ゲーム内で列車が実際に存在するか
- 検索範囲が広すぎないか

### Q: state が 6 にならない

**原因**: 列車が走行していない

**解決**: ゲーム内で列車を発車させてから確認

### Q: オフセットを設定してもツールが動かない

**デバッグ方法**:

```python
# memory_scanner.py を直接編集してデバッグ出力
print(f"Convoy object at: {hex(convoy_addr)}")
print(f"Name address: {hex(convoy_addr + name_offset)}")
print(f"Read bytes: {mem_data[:20].hex()}")
```

## まとめ

x64dbgでシンボルなしでも、以下の手順でオフセットを見つけられます：

1. **文字列検索**で列車名を見つける
2. **アドレスから逆算**して convoi_t の開始位置を推定
3. **ダンプで構造を確認**（vtable, state など）
4. **offsets.json に記録**して試す
5. **動かなければ微調整**（±0x10 ずつ試す）

最初は時間がかかりますが、1回見つければずっと使えます！
